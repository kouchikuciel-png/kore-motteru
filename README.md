# kore-motteru

家庭の所有物と購入予定を重ねて、重複を「禁止せず警告」する共有状態アプリの初号機。

## 目標

2026-10-06 に新井くんが実生活で使い始められる状態にする。

初号機の中心ユースケースは絵本。

- 家主が持っている本を登録する
- 祖父母など第三者が所有リストを見る
- バーコードで所有・購入予定を確認する
- 重複していても購入は禁止しない
- 「重複しています。それでも買いますか？」と判断を人に返す
- 複数人の購入予定をレイヤーとして重ねる

### レイヤー実証

同一コードで以下を実機確認済み。

- owned_quantity = 1
- planned_quantity = 2
- さらに数量2を購入予定へ追加
- planned_quantity = 4 へ更新

よって「重複は検知するが、禁止しない」モデルはGREEN。

## 家主登録ライン

実機試験で以下を確認した。

- ISBN文字認識から新規登録できる
- 同じISBNをバーコードで読むと既存品として検知できる
- 家主側では既存品の数量を増やせない
- 日本の書籍の2段バーコードで、ISBNではない `192...` 側も別コードとして認識される

この結果を受け、家主登録は `011_owner_quantity_registration.sql` で次の形へ更新する。

- 読み取った時点ではまだ登録しない
- 新規・重複どちらでも数量を `− / ＋` で指定してから確定する
- 数量の初期値は1、最小値も1
- 重複時の文言は本専用にせず「同じものを登録しますか？」とする
- 重複時は現在の所有数量を表示し、確定した数量だけ加算する
- 本登録では有効なISBN-13（978 / 979 + 正しいチェック桁）だけ採用する
- 日本の書籍の価格・分類側バーコードなど、ISBNではないEAN-13は無視する
- ISBN印字OCRでもISBNバーコードでも同じ登録UIへ合流する

### 次の受入ゲート

`011_owner_quantity_registration.sql` をSupabaseへ適用し、家主URLをiPhone Safariで開いて確認する。

#### A. 新規本を複数冊まとめて登録

1. 未登録ISBNを読む
2. 数量UIが1で表示される
3. `＋` で3にする
4. 登録する
5. 所有数量が `×3` になる

#### B. 同じ本を追加

1. Aと同じISBNをもう一度読む
2. 「同じものを登録しますか？」と表示される
3. 「現在の所有数量 ×3」と表示される
4. 追加数量を2にして確定する
5. 所有数量が `×3 → ×5` になる

#### C. 日本の書籍2段バーコード

例:

- ISBN側: `9784058008096`
- 価格・分類側: `1920037017002`

同じ画面に2本見えても `1920037017002` は登録候補にせず、ISBN側だけを採用する。

#### D. ISBN印字OCR

例: `ISBN978-4-19-862573-3`

- ISBN文字を自動認識
- `9784198625733` へ正規化
- ISBNチェック桁を通過
- バーコード読取と同じ数量UIを表示
- 指定数量で登録できる

A〜Dが通れば「家主登録ライン GREEN」。

## セキュリティ原則

- 生の共有トークンはDBへ保存しない
- DBにはSHA-256ハッシュだけ保存
- OWNERとSHOPを分離
- ブラウザからテーブルを直接読まない
- SECURITY DEFINER RPC 経由のみ
- 商品→所有者の逆引きAPIを作らない
- 家庭IDや家庭の全データを第三者へ直接公開しない

## データ設計の原則

「あとから再現できない事実は、発生時に記録する」。

主なイベント:

- REGISTER
- CHECK_MATCH
- CHECK_NOT_FOUND
- SCAN_FAILED
- DELETE

家主が数量を追加した場合も `REGISTER` として記録し、metadata に追加数量と更新前後の数量を残す。
