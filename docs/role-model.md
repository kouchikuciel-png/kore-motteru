# オーナー / ゲストの役割分離

## 目的

同じ家庭在庫を扱っていても、家主と第三者では必要な操作が違うため、初号機では画面と権限を分ける。

## オーナーモード

家庭の在庫を作る側。

- 新しい物を登録できる
- 既にある物の数量を追加できる
- 重複時は現在数量を確認して、追加数量だけ加算する
- ゲストから届いた「渡した」を受け取り待ちとして確認できる
- 「受け取った」を押した時だけ在庫へ数量を加算する
- OWNERトークンを使用する

初号機では削除・減算は後続工程とし、誤操作を増やさない。

## ゲストモード

家庭の在庫を参照し、買う側の意思を追加する側。

- 登録済み在庫を閲覧できる
- バーコードで「持ってる？」を確認できる
- 購入予定を追加できる
- 実際に渡した時は「渡した」を登録できる
- 「渡した」は受け取り待ちを作るだけで、在庫を直接増やさない
- 既存在庫の削除・減算はできない
- SHOPトークンを使用する

## 重要な原則

「モード切替」は見た目だけの切替にしない。

OWNERとSHOPは別トークンのまま維持し、ゲスト画面からオーナー権限へ昇格できない設計にする。

UIでは、現在どちらの画面かが一目で分かるように「オーナーモード」「ゲストモード」を明示する。

## 初号機の対応関係

- `owner.html` = オーナーモード
- `index.html` = ゲストモード

既存の登録・重複加算・所有一覧・購入予定レイヤーに、受け渡しレイヤーを追加する。

受け渡しの状態遷移は次で固定する。

`購入予定 → 渡した（受け取り待ち） → 受け取った → 在庫`

ゲストが「渡した」を押しても在庫は増えない。オーナーが現物を受け取り「受け取った」を押した瞬間だけ在庫へ加算する。これにより、ゲストから在庫を直接変更する権限は与えず、オーナー側も本を毎回ゼロから登録し直す必要を減らす。
