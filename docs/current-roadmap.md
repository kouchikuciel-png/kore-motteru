# 現在地と次工程

## 現在地

本の登録ラインは、読み取り・書誌情報・数量指定・重複加算まで実機で前進している。

表紙取得は実機で複数冊の表示成功を確認した。

- ケチャップマン2
- 崖の上のポニョ
- 探偵ガリレオ

さらに、既登録の「崖の上のポニョ」では現在所有数量 ×1 を正しく表示し、そのまま追加数量UIへ進めた。
未登録の「探偵ガリレオ」でも表紙・タイトル・著者を表示して新規登録UIへ進めた。

このため、表紙取得と本登録の基本導線は安定GREENとして扱い、今後は新しい不具合が出ない限り読み取り・表紙ロジックを不用意に変更しない。

役割は次で固定する。

- オーナーモード: 家庭在庫を作る。新規登録と既存在庫への数量追加ができる。
- ゲストモード: 家庭在庫を参照する。所有確認・購入予定への追加・「渡した」の記録ができる。
- 「渡した」は受け取り待ちを作るだけで、在庫はまだ増やさない。
- オーナーが「受け取った」を押した時だけ在庫へ加算する。
- ゲストは在庫の直接追加・削除・減算をしない。

## 裁可なしで進める範囲

既存仕様を変えず、壊れにくくする作業は自律進行する。

- オーナー / ゲストの表示を明確にする
- 既存画面の文言・タップ領域・読みやすさを整える
- 回帰テストを固定する
- 表紙失敗時の診断を成功時には隠す
- 一覧カードの見え方を統一する
- README / 設計資料 / 現在地を更新する
- 既存GREENを壊していないか確認する

## 次の裁可ポイント

以下はデータの意味・権限・主要UXを変えるため、実装前に裁可を取る。

### 1. ゲストの「追加」の意味（裁可済み）

次で固定する。

`購入予定 → 渡した（受け取り待ち） → 受け取った → 在庫`

ゲストは在庫を直接変更しない。実際に渡した事実を登録し、オーナーの受取確認で初めて在庫へ反映する。

### 2. スクショ / 手入力での「持ってる？」確認

候補:

- 商品名検索
- スクショOCR
- バーコード番号の直接入力
- 複数候補が出た時の選択方法

### 3. 在庫の減算・削除

決めること:

- オーナーだけに許可するか
- 誤操作防止をどうするか
- 履歴を必須にするか

## 次の受入ゲート

まず本だけで次の一周を成立させる。

`読む → 登録 → 一覧で確認 → もう一度読む → 重複を確認 → 数量を追加`

現在、読み取り・書誌情報・表紙表示・重複検知・追加数量UIまでは実機で通っている。
残る確認は、登録後の一覧反映と、同じ本への数量追加が最後まで正しく保存されること。

このループと「渡した → 受け取った → 在庫」の受け渡しループが安定したら、ゲストの検索・スクショ確認へ進む。
その後に牛乳・卵など一般商品の在庫へ構造を転用する。
