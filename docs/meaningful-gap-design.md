# 「意味のある穴」設計メモ

## 目的

プレゼントする側の根底にある「喜んでもらいたい」を助ける。

単なる未所持一覧ではなく、既に持っている物との関係から「贈る理由がある未所持」を見つける。

## 穴の種類

### 1. 明確な連番の穴

例: 1・2・3・5巻を所持し、4巻だけ未所持。

表示理由:
「このシリーズを4冊持っていますが、4巻だけ未所持です。」

### 2. シリーズの続き

例: 1〜5巻まで所持し、6巻以降が未所持。

表示理由:
「このシリーズを5冊持っています。次は6巻です。」

### 3. 系譜の穴

本編は所持しているが、スピンオフ・番外編・関連シリーズが未所持。

表示理由:
「本編を持っていますが、関連作のこの1冊は未所持です。」

### 4. 作者・世界観の穴

同じ作者や同一世界観の作品を複数持つが、代表的な関連作が未所持。

表示理由:
「同じ作者の本を複数持っています。」

### 5. 入手しにくさ

未所持候補に、絶版・品薄・限定版・特装版などの入手難度を重ねる。

これは鮮度のある外部情報が必要なので、初版では推測しない。
外部データ源と更新頻度を決めてから実装する。

## 表示原則

候補を出す時は、必ず「なぜ候補なのか」を一緒に出す。

悪い例:
「おすすめです」

良い例:
「1〜5巻と7巻を持っています。6巻だけ未所持です。」

## 所持表示

系譜・シリーズ画面では、一目で穴が見える形を基本にする。

- ✓ 所持
- ○ 未所持
- ◇ 受け取り待ち
- △ 購入予定

来歴表示がONなら、所持行に「じいじから」等を添えられる。
来歴表示OFFなら人物情報は出さない。

## データ構造の方向

ISBN単体だけでなく、作品と版を分けて考える。

- work: 作品そのもの
- edition: ISBNごとの版
- relation: 本編 / 続巻 / スピンオフ / 関連作
- series_order: 巻数や順序
- household_state: 所持 / 購入予定 / 受け取り待ち

同じ作品の通常版・特装版を「同じ」とみなすかは自動決定しない。
プレゼント用途では版違い自体に価値があるため、作品単位と版単位を両方保持する。

## 初版後の実装順

1. 既知シリーズ1つで手動データを使いUI検証
2. 所持 / 未所持 / 購入予定 / 受取待ちの重ね表示
3. 「なぜ候補か」の理由表示
4. シリーズ・関連作データ源を決定
5. 入手難度データを追加

最初から全書籍の相関図を作らず、1シリーズで「探したくなるか」を検証してから広げる。
